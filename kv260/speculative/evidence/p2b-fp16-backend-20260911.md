## Implemented datapath

- P2-A scheduler directly feeds one shared numerical pipeline.
- 128 production lanes instantiate `fp16int9d4`; signed W4 `q-zero` values are
  sign-extended to the IP input.
- The converter output receives the same exponent-field divide-by-four as
  `util.Fp16ScaleDown.vec(..., 2)`.
- One `fp16mul6` per lane is shared by legacy GEMV and speculative GEMM.
- Four banks each reduce 32 FP16 products using balanced `fp16add6` trees.
- Bank totals convert through `fp16toFp32`, reduce through `fp32add11`, multiply
  the group scale through `fp32mul8`, and accumulate through `fp32acc22`.
- Four small accumulator contexts are selected by token index. They preserve
  independent K rows without duplicating conversion, multiplication, or
  reduction hardware. Results return through `fp32toFp16` with row/token tags.

The production instance contract is 128 `fp16int9d4`, 128 `fp16mul6`, 124
`fp16add6`, five `fp16toFp32`, three `fp32add11`, one `fp32mul8`, four
`fp32acc22`, and four `fp32toFp16` instances.

## Numerical acceptance

Command:

```powershell
kv260/speculative/rtl/run_p2b_xsim.ps1
```

The script generates its golden data by calling the frozen P1
`gemm_reference`, then simulates the real Vivado 2022.2 Floating-Point IP
models. The regression uses an 8-lane/4-bank reduced geometry for tractable
event-level runtime while preserving every arithmetic stage and rounding
boundary. Production defaults remain 128 lanes/4 banks.

Observed marker and counts:

```text
P2B_REFERENCE 4200 be00 4500 c100 4700 c300 4880 c480
P2B_K1 outputs=2 weight_beats=4
P2B_K2 outputs=4 weight_beats=4
P2B_K3 outputs=6 weight_beats=4
P2B_K4 outputs=8 weight_beats=4
P2_W4_FP16_BACKEND_GO bit_exact_K1_to_K4=1
```

Acceptance result: all 20 produced FP16 outputs match the P1 bit patterns, and
accepted target-weight traffic is four beats for every K.

The complete P1 unit suite also passes: 12 tests, including GEMM versus repeated
GEMV for K=1..4 and `Fp16ScaleDown` bit semantics.
